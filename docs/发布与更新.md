# 发布与更新流程

> 这份文件回答一个问题：**以后每次改完，怎么把它安全地送出这台机器。**
> 项目是单人维护 + 多个 AI agent 并行改，所以规则比常规团队更严一点，重点防「互相覆盖」。

## 一、日常改动（每次都用这套）

```bash
cd ~/WanFlow
git pull                      # 1. 先同步（多设备/多 agent 必须）
cat STATE.md                  # 2. 看别人做到哪、有没有阻塞
#   ... 改代码 ...
npm run build                 # 3. 前端必须能构建通过
git status --short            # 4. 只看自己改的文件
git add <自己的文件>            # 5. 精确 add，禁止 git add -A
git commit -m "feat: 一句话说明"
git push
```

**第 5 步是这套流程里最重要的一步。** 仓库里同时可能有 Codex、Claude Code、DSH 在改，
`git add -A` 会把别人写了一半的代码卷进你的提交。

## 二、提交信息

```
<type>: <一句话>
```

| type | 什么时候用 |
|---|---|
| `feat` | 新功能 |
| `fix` | 修 bug |
| `perf` | 只改性能 |
| `refactor` | 不改行为的结构调整 |
| `docs` | 只改文档 |
| `chore` | 构建、依赖、配置 |

一次提交只做一件事。合并多个不相关的改动时拆开提交。

## 三、发版（对外发安装包时）

**版本号要同步改三处**，漏一处会出现「应用显示 0.1.0、安装包是 0.2.0」：

| 文件 | 字段 |
|---|---|
| `package.json` | `version` |
| `src-tauri/tauri.conf.json` | `version` |
| `src-tauri/Cargo.toml` | `version` |

然后：

```bash
git add package.json src-tauri/tauri.conf.json src-tauri/Cargo.toml CHANGELOG.md
git commit -m "chore: 发布 v0.2.0"
git tag v0.2.0
git push && git push origin v0.2.0

npm run tauri build           # 本机出安装包，产物在 src-tauri/target/release/bundle/
```

`CHANGELOG.md` 用「用户能感知的变化」来写，不写重构细节。最新版本放最上面。

## 四、回滚

| 场景 | 做法 |
|---|---|
| 刚提交、还没推 | `git reset --soft HEAD~1` |
| 已推送、想撤销某次提交 | `git revert <sha>`（生成一个反向提交，不改历史） |
| 发出去的版本有问题 | 发一个新 tag（如 `v0.2.1`）修掉，**不要删已发布的 tag** |
| 工作区被改乱了 | `git checkout -- <文件>`（只适用于未提交改动） |

## 五、多 agent 并行时的三条硬规矩

1. **禁止 `git add -A` / `git commit -a`**，永远精确指定文件。
2. **提交前 `git diff --stat`**，出现不是你改的文件就停下来问。
3. **开工先读 `STATE.md`，收工更新它 + 在 `HANDOFF.md` 追加一段。** 对话会消失，文件不会。

## 六、CI 的缺口（现状如实记录）

`.github/workflows/ci.yml` 目前只跑**前端构建**（`npm ci` + `npm run build`）。

Rust / Tauri 侧没进 CI，原因是它依赖 onnxruntime、图像解码等原生库，需要先固定
各平台的系统依赖和预编译产物。补齐的顺序建议：

1. 先在本地跑通 `cargo test --manifest-path src-tauri/Cargo.toml`；
2. 给 `quality.rs`、`phash.rs`、`scanner.rs` 这三个纯函数模块补单元测试（当前 0 测试）；
3. 测试稳定后再加一个 `tauri-apps/tauri-action` 的构建 job，避免 CI 长期红。

**现在这个仓库的测试覆盖是 0，lint 也是 0。** 在补上之前，`npm run build` 通过是唯一的自动关卡。

## 七、公开仓库的边界

这个仓库是公开的，因此：

- 不提交真实用户照片/视频（测试素材一律放 `tests/fixtures/` 且用合成图）
- 不提交 `.env`、证书、密钥（`.gitignore` 已覆盖）
- 不提交 agent 工具状态目录（`.v2c/`、`.video_agent/` 等含本机绝对路径）
- 提交前跑一次：`git ls-files | grep -iE "\.(jpg|mov|db|pem)$"` 人工确认
